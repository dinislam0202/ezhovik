# Ежовик и наука

Научно-популярное издание о ежовике гребенчатом (*Hericium erinaceus*). Next.js (App Router) + TypeScript + Tailwind CSS 4. Все страницы генерируются статически.

## Запуск

Нужен Node.js 20.9 или новее.

```bash
npm install
npm run check:data   # проверка целостности данных (источники, ссылки, поиск)
npm run dev          # http://localhost:3000
npm run build        # production-сборка
npm start            # запуск собранной версии
```

Перед публикацией задайте адрес сайта, иначе canonical, sitemap и Open Graph будут указывать на localhost:

```bash
NEXT_PUBLIC_SITE_URL=https://example.org npm run build
```

И впишите контактный адрес редакции в `data/site.ts` (`contactEmail`).

## Как добавить исследование

Правило проекта: **ничего не добавлять по памяти.** Каждая запись сверяется с первичной страницей (PubMed, PMC, сайт издателя).

1. Откройте `data/research.ts` и добавьте объект в массив `research` по образцу существующих.
2. Заполните только то, что подтверждено источником. Неподтверждённое поле опустите, а `verification.status` поставьте `"partial"` и опишите в `note`, что проверить. Такая карточка получит пометку «Требует проверки».
3. Добавьте короткий ключ в `citeKeys` (например, `smith2027: "smith-2027-..."`). Он нужен для ссылок `[[cite:smith2027]]` в текстах.
4. Дозировки и режимы приёма не приводите.
5. Запустите `npm run check:data`: скрипт проверит дубликаты, формат DOI/PMID, наличие результатов и ограничений.

Карточка автоматически появится в каталоге, поиске, sitemap и на странице `/research/<id>`.

## Как добавить статью

1. Добавьте объект в массив `articles` в `data/articles.ts`: `slug` (латиницей), `title`, `description` (80–200 символов), даты, `related`, `glossary` и `blocks`.
2. Блоки: `h2`/`h3` (с уникальным `id` для оглавления), `p`, `list`, `callout` (`known`, `unproven`, `limits`), `figure`, `table`, `diagram` (`stages` или `map`).
3. Внутри текста:
   - `[[cite:mori2009]]` — номерная ссылка на источник (список литературы строится сам);
   - `[[term:erinacines|эринацинами]]` — ссылка на термин словаря;
   - `[[link:/safety|безопасность]]` — внутренняя ссылка;
   - `**жирный**`.
4. Запустите `npm run check:data`: он найдёт битые ссылки на источники, термины и маршруты.

Страница статьи, оглавление, время чтения, JSON-LD, хлебные крошки и sitemap создаются автоматически.

## SEO

- Уникальные `title` и `description`, canonical, Open Graph и Twitter Card на каждой странице.
- `sitemap.xml` и `robots.txt` генерируются из данных.
- JSON-LD: `Organization`, `WebSite` (с `SearchAction`, который ведёт на `/library?q=...`, поиск реально поддерживает этот параметр), `BreadcrumbList`, `Article`. Медицинская и товарная разметка не используется.
- Один `h1` на страницу, ЧПУ на латинице, хлебные крошки.

## Что важно знать

- **Изображения.** В проект не включены фотографии: при разработке не было доступа к источникам с проверяемой лицензией. Иллюстрации — собственные схемы в SVG (`components/Illustration.tsx`), на сайте они подписаны как условные рисунки. Реальные фото можно добавить, указав автора и лицензию в подписи (например, материалы Wikimedia Commons с подходящей лицензией); не выдавайте иллюстрации за микроснимки.
- **Научные базы.** Автоматической интеграции с PubMed или другими базами нет: каталог ведётся вручную. Страница «Библиотека» даёт ссылки на базы, но не делает вид, что они подключены. Для подключения PubMed E-utilities создайте серверный модуль в `lib/` и вызывайте его из скрипта обновления, а не из браузера.
- **Записи «Требует проверки».** У двух обзоров (`ma-2010-...`, `thongbai-2015-...`) часть реквизитов подтверждена не полностью. Они помечены на сайте и в списке на странице «О проекте».
- **Дисклеймер** хранится в `data/site.ts` и выводится в подвале и на ключевых страницах.
